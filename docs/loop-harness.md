# Loop Harness

## 目标

用 Harness 控制 Codex 自动研发交易策略：

- 0 → 1：从研究假设开发新策略。
- 1 → N：迭代优化已有策略。

要求：

- 自动运行多个轮次。
- 每轮使用独立 Codex 会话。
- 只继承通过评测的改动。
- 实验可记录、可恢复。
- 不连接实盘交易。

## 理想工作流

1. 人工定义研究目标、数据范围、固定 baseline、评测指标、风险约束和最大轮数。
2. Harness 从当前最佳版本 `champion` 创建候选实验。
3. Harness 启动新的 Codex 会话，并提供任务、champion、历史摘要和修改范围。
4. Codex 提出一个假设，修改代码，运行测试和回测，输出结构化结果。
5. Harness 将候选同时与 champion 和固定 baseline 比较。
6. 候选通过则更新 champion；未通过则恢复原 champion。
7. Harness 保存实验记录，并自动启动下一轮。
8. 达到轮数、超时、连续失败或人工中止时结束。

```text
读取状态 → 创建候选 → 新建 Codex 会话 → 开发与回测
→ 自动评测 → 更新或恢复 champion → 保存状态 → 下一轮
```

## 所需技术

- 任务配置：目标、数据、baseline、指标、约束、修改范围和循环预算。
- 单轮执行器：启动独立 Codex 会话并获取结构化结果。
- 测试与回测：复用 pytest 和 `quant_core` CLI。
- 实验存储：保存 champion、代码差异、指标、结论和运行状态。
- 准入规则：程序判断候选是否通过，Codex 无权决定晋级。
- 循环控制器：管理轮次、超时、失败停止、中断恢复和人工终止。

## 分阶段目标

### 阶段一：定义任务格式

完成任务配置和单轮实验结果格式。

验收：可以人工生成一份结构固定的实验记录。

### 阶段二：打通单轮研发

实现独立 Codex 会话的启动、开发、测试、回测和结果输出。

验收：一条命令生成完整的 `experiment-001`。

### 阶段三：管理实验状态

实现 baseline、champion、候选版本、接受、拒绝和恢复。

验收：失败实验不会污染下一轮。

### 阶段四：实现自动循环

自动启动每轮独立会话，加入轮数、超时、连续失败和恢复机制。

验收：一次启动自动完成 3 轮实验。

### 阶段五：验证两类任务

分别运行一个 0 → 1 新策略研发任务和一个 1 → N 策略优化任务。

验收：均能输出候选策略、实验对比和最终结论。

MVP 暂不实现数据库、多 Agent、并行搜索、通用评测平台、自动部署和实盘交易。
